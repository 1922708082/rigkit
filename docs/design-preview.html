01

现状诊断：能力很强，结构很险

现有项目已经把矿卡改造这件事跑通了，但它的成功依赖作者对细节的记忆，而不是一套可复制的工程结构。

底层引擎

NativeCore 上帝类

400 KB、205 个方法，注册表、BCD、EFI、省电、伪装、更新全在一个文件里。

界面

206 KB 单文件 XAML

12 个页面与全部样式塞在一起，控件重名会导致整窗加载失败。

权限

全进程管理员

UI、网络、AI、硬件写入同权限运行，攻击面与稳定性风险都被放大。

发布

47.5 MB 资源全量内嵌

每次发版全量替换，启动解压慢，更新链路依赖解析 GitHub 页面。

六个必须解决的问题

P1
上帝类与单文件页面改一处牵动全局，无法单测、无法并行开发
对策按 Capability 拆分 Handler，每页独立 View，建立组件库
P2
没有事务与快照备份分散在各功能里，失败后靠用户自救
对策预检 → 快照 → 执行 → 验证 → 自动回滚，快照带哈希与差异
P3
新卡型必须改代码发版支持周期以周计，长尾卡型覆盖不了
对策签名规则包描述卡型、能力、参数与已知坑，客户端只做执行引擎
P4
AI 只是关键词匹配复杂表达匹配不到，不能多步执行，执行日志被丢弃
对策工具调用 + 计划编排 + 逐步确认 + 执行解释
P5
更新链路脆弱国内网络不稳，无签名校验、无灰度、无回滚
对策自建 manifest + 自有 CDN + Ed25519 签名 + 通道与回滚守卫
P6
设计语言未 token 化样式硬编码，无深色模式，缺少错误态与空状态
对策Design Token + 统一组件 + 浅色/深色双主题 + 三态覆盖

判断：这是一次「产品化重构」，不是「换皮重写」。底层经验全部保留，工程结构与安全边界重建；RigKit 作为独立新版本开发，不迁移旧配置、不做兼容层。

首版新增：P 系列不是 CMP 的复制品

型号架构显存视频输出图形能力支持级别（统一 Experimental）
P102-100GP10210 GB GDDR5X无无官方图形驱动实验性：识别 / 体检 / 调优 / 计算
P104-100GP1048 GB GDDR5X无社区驱动有限实验性：识别 / 体检 / 调优 / 计算
P106-100GP1066 GB GDDR5无修改驱动可游戏实验性：识别 / 体检 / 调优 / 游戏（受限）
P106-090GP1063 GB GDDR5无不建议实验性：识别 / 体检 / 计算（PCIe x1）

P 系列整体标记 Experimental，这是产品决策，不是临时状态。即使体检全绿也只显示“实验性”，不承诺长期稳定性。升级为 Supported 需要至少 3 张不同型号真机、30 天连续运行、无不可恢复故障、驱动来源可追溯。

红线一

不捆绑修改驱动

只做驱动状态检测、版本建议、签名校验与回滚；驱动由用户从可信来源获取。

红线二

不承诺图形解锁

P 系列无视频输出，必须依赖核显输出；P102/P104 基本不适合游戏，P106-100 仅实验性。

红线三

不写 vBIOS

只读备份与校验，避免把体检工具变成变砖工具。

02

产品定位：矿卡的全生命周期工作台

解决的不是“怎么挖矿”，而是“怎么把一张能力受限、来路不明的矿卡，安全地变成可验证、可调优、可长期使用的生产力设备”。

Slogan
让每一张矿卡，
有据可查，有路可退。

Know your card. Keep a way back.

买前敢买

10 分钟出一份可分享的验卡报告：温度、显存、PCIe、稳定性、矿龄推断，结论直白。

买后能用

解锁 PCIe、恢复图形能力、伪装型号、修驱动、开覆盖、上 DLSS，全程预检与回滚。

长期好养

场景 Profile、异常告警、快照恢复、诊断包导出，掉驱动也能一键回到昨天。

三类核心用户

买

二手买家

预算敏感，怕买到暗病卡。

  • 面交前快速验卡
  • 报告能发给朋友复核
  • 结论要直白，不要术语
玩

矿卡玩家

1~2 张 CMP，打 3A、跑本地 AI。

  • 一次解锁成功
  • 失败能退，别变砖
  • 游戏覆盖与 DLSS 要能用
店

工作室 / 装机店

5~50 张卡，接渲染或推理单。

  • 批量体检与统一调优
  • 可交付的报告
  • 配置可复现、可回滚

03

系统架构：把“管理员权限”关进笼子

核心变化不是换框架，而是换权限模型。UI 永远不提权，所有写操作经过一个只认白名单命令的 Broker。

04

模块划分：让每一块都能独立验收

按“领域”而不是“页面”切分。页面只是入口，真正的边界在能力与事务。

01 Device

设备与能力

枚举、指纹、状态、能力矩阵。以 PCI 位置为主键，解决多卡错位。

02 Health

体检与评分

8 项检测、加权评分、报告生成、基线对比。

03 Operation

操作事务

计划、预检、快照、执行、验证、回滚。

04 Snapshot

快照与恢复

注册表、BCD、文件、驱动状态，差异对比。

05 Tune

调优 Profile

功耗墙、频率、风扇曲线、场景与应用绑定。

06 Ecosystem

生态补丁

覆盖解锁、DLSS 运行库、RE 框架，可还原。

07 Rules

规则包

卡型、能力、参数、已知坑，签名热更新。

08 Copilot

AI 与诊断

工具调用、计划生成、执行解释、离线降级。

一次写操作的数据流 核心事务

STEP 01
用户动作
点击「安全解锁」，UI 只发意图，不碰系统。
STEP 02
生成计划
10 项预检 + 步骤 + 风险 + 回滚方式。
STEP 03
确认与快照
高危输入确认词，Broker 创建带哈希快照。
STEP 04
执行与推送
逐步执行，事件流回 UI，日志实时可见。
STEP 05
验证与提交
PnP 状态、Code 43/14、PCIe 速率、驱动版本。
ON FAIL
自动回滚
逆序还原；失败升级人工干预 + 救援入口。
启动数据流

从双击到看见数据

单实例检查 → 加载配置与规则包 → 按需拉起 Broker → 设备枚举 → 能力匹配 → 1s 传感器轮询。任一步失败都有降级路径，不阻塞进入工作台。

传感器数据流

NVML 优先，三级降级

NVML → nvidia-smi → WMI → UNKNOWN。UI 明确标注数据来源与新鲜度，缺失值显示 --，绝不写成 0 误导判断。

规范要点

排版

数字用仪表字体

Bahnschrift + tabular numerals；温度 1 位小数、功耗 1 位、频率取整。中文用 Microsoft YaHei UI，避免字体授权与体积。

布局

44 + 232 + 12 栅格

默认 1360×860，最小 1180×720。侧栏可折叠，右栏可收起，200% 缩放不破版。

动效

短、稳、可关闭

悬停 120ms，页面 180ms，弹层 240ms；传感器数值补间 300ms，尊重“减少动态效果”。

文案

说人话，给下一步

错误三段式：发生了什么 → 为什么 → 现在可以做什么。不写“永久解锁”“百分百成功”。

可访问性

不只靠颜色

状态必须配图标或文字；正文对比度 ≥ 4.5:1；全键盘可达；最小点击区 32×32。

禁区

不做电竞风

不用 RGB 渐变、霓虹、金币矿机插画、过度玻璃拟态。危险操作绝不做成主色实心按钮。

开源签名：三条路线组合

路线作用成本限制
Certum Open Source 主签名Authenticode，消除“未知发布者”，SmartScreen 信誉可积累约 €69~100/年需身份验证与开源项目链接，仅限开源软件
Sigstore cosign 透明签名证明发布物来自本次 CI 构建，写入 Rekor 透明日志免费不替代 Windows Authenticode，不消 SmartScreen
SignPath Foundation 可申请免费 OV 级签名，HSM 托管，CI 集成免费需审核；硬件解锁类可能被认定为绕过安全措施

首版组合：Certum 主签 + Sigstore 透明签名 + SHA-256 清单；SignPath 并行申请，通过后作为第二签名或替代。自签名只用于内部测试。

分发渠道

四条腿走路

官网 muyaa.top/rigkit 为主入口；dl.muyaa.top 走腾讯云 COS + CDN；GitHub Releases 做海外与归档；蓝奏云 / 123 云盘做国内镜像。所有渠道同一哈希。

信任建设

开源比广告更能消除戒心

源码公开 + 可复现构建 + Certum 开源签名 + Sigstore 验证命令；同步提交微软 SmartScreen 与国内杀软白名单，公布 SHA-256 与 VirusTotal。首版仍可能有少量警告，这是信誉积累过程。
